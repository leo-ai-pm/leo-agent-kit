# 项目交付

[文档导航](README.md) · [命令参考](cli.md)

交付模块负责把已确认的需求变成分阶段任务，保存状态和验收证据。需要编码助手在工作区内完成实现；CLI 本身负责初始化、交接和调用阶段管理脚本。

## 初始化与导入

在工具箱根目录执行：

```bash
python3 leo.py init my-agent
python3 leo.py handoff my-agent /绝对路径/工坊输出目录
python3 leo.py delivery my-agent task
```

导入目录必须有非空 UTF-8 文件 `PRD.md` 与 `方案.md`。工具会先检查两份文件，再写入目标目录；拒绝符号链接输入和已有同名文档，避免误覆盖。

没有工坊方案时，也可以只初始化工作区，让编码助手按照需求模板完成访谈与 PRD。此时无需调用 `handoff`。

## 用编码助手打开工作区

打开 `workspace/my-agent/`，使用以下指令：

```text
请读取本工作区根目录的 AGENTS.md，处理产品 my-agent。
先看 projects/my-agent/docs/PRD/ 中的需求和方案，再读取当前阶段任务。
按阶段实现，记录待确认事项，完成后提供自检结果和可复核的验收证据。
```

每个工作区都包含自己的规则与手册，不需要同时打开三个源码模块。代码、状态和证据写入该工作区中的产品目录。

## 目录与职责

```text
workspace/my-agent/
├── AGENTS.md                   # 编码助手的规则
├── CLAUDE.md                   # 规则入口
├── kit.sh                      # 阶段管理器
├── verify.sh                   # 自检脚本
├── leo-project.json            # 产品名与交接摘要
├── docs/                       # PRD 模板及技术手册
└── projects/my-agent/
    ├── docs/
    │   ├── PRD/                # 导入的 PRD.md 与 方案.md
    │   ├── 设计参考/            # 视觉参考与截图
    │   ├── 阶段文档/            # 各阶段方案与补全清单
    │   ├── evidence/           # 各阶段验收证据
    │   ├── 项目状态.md          # 决策与进度，由编码助手维护
    │   ├── 本阶段任务.md        # 以下三项由阶段管理器生成
    │   ├── 流程状态.txt
    │   └── 流程历史.txt
    ├── backend/                # 实现时生成
    └── frontend/               # 实现时生成
```

初始化只生成模板与基础目录。任务、状态、代码和证据随工作进展产生。

## 六阶段流程

| 阶段 | 工作重点 | 主要产物 |
|---|---|---|
| 0 PRD 体检 | 明确目标、边界与未定事项 | PRD 补全清单、决策与状态记录 |
| 1 技术适配 | 选择实现方式，拆分子阶段 | 技术适配声明与阶段范围 |
| 2 后端 MVP | 打通核心链路 | 代码、测试、真实模型验证记录 |
| 3 正式前端 | 实现交互与适配 | 页面、构建结果、使用流程验证 |
| 4 上线 | 配置部署并验证运行 | 部署说明、权限与数据检查 |
| 5 收尾 | 整理运行和维护资料 | 产品 README、最终状态 |

阶段 2 与阶段 3 可分为多个子阶段。模板附带 CloudBase 部署手册；实际部署前应按项目需求确认账号、资源与费用，不由初始化命令创建云资源。

## 自检与验收

```bash
python3 leo.py delivery my-agent task
# 编码助手在工作区中完成当前阶段
python3 leo.py delivery my-agent check
python3 leo.py delivery my-agent status
```

自检不是应用效果的全部证明。无代码阶段检查对应文档；有代码阶段还要检查测试、模型冒烟记录、构建、密钥排除和数据恢复等项目。

只有实际验收通过后，才执行：

```bash
python3 leo.py delivery my-agent accept --confirmed
```

需要选择下一子阶段时，按阶段管理器提示加 `--next-stage`。缺少 `--confirmed` 会被工具箱拒绝；底层管理器还会检查自检状态。该标志表示操作者确认，不是身份认证或防篡改审批。

## 证据包

证据放在 `projects/my-agent/docs/evidence/<阶段名>/`：

| 文件 | 用途 |
|---|---|
| 页面或接口截图 | 查看实际运行结果 |
| `照着做清单.md` | 用户可复现的验收步骤 |
| `是否表.md` | 本阶段检查结论与证据指向 |
| `verify-输出.txt` | 自检脚本的原始输出 |
| `冒烟记录.md` | 涉及模型时，由实际调用脚本记录验证结果 |

具体要求以当前阶段任务为准。没有运行真实模型时应记录待验，不能用 mock 结果替代。

## 文档再次变更

`handoff` 只导入 PRD 和方案，并在 `leo-project.json` 保存当时内容的 SHA-256 摘要。它不自动同步之后的修改，也不会把工坊的 `skeleton/` 复制到交付目录。

后续需求变更要明确哪些文档是当前版本，保留旧稿，再在工作区更新实现和验收计划。不要直接覆盖阶段管理器维护的状态文件。
